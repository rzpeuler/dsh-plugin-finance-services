# 失败记录：成果"打开会话"点击无响应（2026-11-06）

- 现象（用户报告）：刷新页面后点击"打开会话"，**界面没有任何反应**——不切换会话，也不显示错误
- 阶段：P6，判据 `P6-DELIVERABLE-OPEN`
- 当时版本：`2a66475`（已构建、已安装、`application: applied`）

## 已排除

- 客户端产物确实包含新代码：`lib/client.js` 中存在 `backToSession` 与 `openSession`（7 处引用）
- 按钮本身已渲染（用户能看到并点击），说明 `openSession` 句柄已传入面板

## 最可能的原因（按概率）

1. **点击被静默吞掉**：处理函数用 `try { ctx.uiWorkspace.openSession(id) } catch {}`，页面拒绝导航时既不抛给界面也不改变状态，于是"无响应"。
2. **成果关联的会话已不存在**：当前成果索引里的 `sessionId` 多来自探针会话，重启后这些会话不再存在，`openSession` 对未知目标静默拒绝。

## 处理决定

不猜测、也不把"无响应"写成通过。改为**让失败可见并可判定**：

- 点击后必须产生可见状态变化（成功提示或失败码）；
- 进入面板时用页面可选的 `sessions` 服务判断会话是否仍存在；不存在的显示"该会话已不存在"，**不再渲染成可点按钮**；
- 无 `sessions` 服务时保持原有行为，但点击仍有可见反馈。

修复完成后再请用户复验；在此之前该判据保持未通过。
