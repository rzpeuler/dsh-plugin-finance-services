## 已知边界和判定规则

- 已逐项核对现有资产manifest：上表10个主ID与其各3个Worker一一匹配，共40角色；不新造/别名复制Agent。最终方法/字段以原persona和Skills映射为准；源worker JSON schema缺字段时不把schema-valid误当业务完整。
- LBO/comps/Nike源二进制模板缺失继续`MISSING_SOURCE_ASSET`；可另做明确命名的有限、独立生成工作簿，但不能冒充源模板恢复或完整等价。
- 商业源未授权时只做明确TEST_ONLY或真正用户提供输入的运行；不暗自请求付费数据、模型猜财务数据或正式业务动作。
- 内部检查/复核要求继续保留；P5 Gate未实现时产物是DRAFT/REVIEW_REQUIRED，不可宣称已审批、已发布或可正式记账/交易/KYC签字。
- 每次真实运行保存不可变run ID、模型/工具/Worker事实与原始失败。产物创建、结构检查、重算、PDF转换、视觉验收分开记录，不用一个静态PASS替代全部。
- 任何关键项未通过时P4不标完成；本文件可追加实际结果，不回写删除初始失败，也不以用户P3阶段例外降低P4标准。

- 两项对照排除了解释并缩小结论：[007 环境对照](P4-office-env-control-007.json)四次同参数调用（覆盖/继承环境）全部同一状态码；[008 读取范围对照](P4-office-confinement-read-control-008.json)连`C:\Windows\System32\cmd.exe`也以同一状态码、空stdout/stderr退出。合计6次固定调用均`0xC0000142`，故既非环境替换、也非解释器所在路径不可读，而是**本机原生受限子进程启动路径本身不可用**。未以无沙箱方式重试。
- 同时核对当前Host公开契约：`ctx.fs`无`writeBytes`/二进制发布，`ctx.subprocess`无Agent/策略字段，`ctx.officeToPdf`只做已存在Office源的PDF转换。因此插件端既不能启动Office生产者，也不能把二进制产物写入工作区；这是独立于P3 MCP缺口的**第二个宿主接口缺口**，需宿主提供受支持的二进制产物写入或可用受限子进程后才能做Agent驱动的Office交付。`ctx.attachments`虽能存二进制，但属附件存储、非工作区成果，不冒充交付路径。
- 结论：P4仍PARTIAL。缺少十项原生业务运行、Office生成/重算/PDF、原生业务Tool注册与await后权限复验、只读Office结构检查；P3的Manager与安全MCP委派缺口不变。

## 进程内 XLSX 写入器（绕过两项封堵的一半）

`src/office/xlsx.js` 用 `node:zlib` 的 CRC32 自建 stored ZIP，直接输出 SpreadsheetML：支持内联字符串、数字、布尔与**带缓存值的公式**，并对工作表名/行列数做上限校验。

- [5项本地测试](P4-xlsx-writer.tap)：ZIP 结构与必备部件、逐条 CRC 校验、单元格 XML、工作表关系、非法结构拒绝、XML 转义。
- [创建者侧验证](P4-inprocess-xlsx-001.json)：openpyxl 能打开该文件，`Model`/`Notes` 两表、数字为 `n`、公式为 `f` 且表达式原样保留，SHA `442e35af…`。

**这没有解除 P4 的阻断**：字节仍无法写入工作区（宿主无二进制写接口），公式也无法重算（无可用受限子进程）。但它证明"生成 Office 内容"这一环不再依赖被阻断的两个宿主能力——下一步只差"把字节交付给用户"的通道。台账 `P4-OFFICE-NATIVE` 据此更新为更精确的阻塞描述。

### 字节交付通道（Remote）

新增 `reviewWorkbook` 读方法：按当前策略与队列事实在进程内构建 xlsx，返回 `filename/bytes/sha256/base64`。原生分发已验证（[4 项](P6-workbook-native-001.json)），返回的字节经 openpyxl 打开（[证据](P4-workbook-over-remote-001.json)）：两表、策略 `original`、digest 前缀、会话数 13、公式单元格类型 `f`。

Client 侧加了唯一一个下载控件：先校验文件名/大小/哈希/ZIP 头与声明长度，再创建**一个** anchor 点击并立即回收 object URL；为此把打包检查从"禁止任何 document.body"改为**精确计数**（全产物仅允许一处 append、一处 click、必须 revoke），其余 DOM 操作仍禁。**浏览器点击下载本人未验证。**

### 十个任务模板的只读读模型（原生）

`financeOperations.taskTemplates` 通过 Remote 返回 10 个已声明的接单模板：预设 id、标题、模板版本、来源检查点与来源引用。它**只报声明**——不授权、不读文件、不启动运行、不表示批准；输出被 `TaskTemplates` 严格 schema 约束并有大小上限。

[4项原生检查](P4-templates-native-001.json)：10 个模板可分发且 id 唯一；每个模板对应的都是主预设；模板带来源检查点（10/10）；输出中不含 `approved`/`signedOff`/`completedAt` 字样；两次读取字节完全一致（无写入）。
